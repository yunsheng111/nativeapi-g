### 1.3 冲突裁决（4 处）

1. **上下文管理**：报告一判「对齐（生态共识验证了本设计）」，报告二判「四项目 + 本项目共同缺失」→ **采纳报告二**。拍平式设计本身仍是生态共识，但长度保护是 7.5.2 早已推导出的「体积代价」欠账；24000 字符截断只覆盖工具结果路径，用户历史无任何治理。**提级 P0**。
2. **写合并 debounce**：报告一列为观察项（C3），报告二论证对本项目不适用（账号落盘是**事件驱动**而非每请求写盘，`store.py:182-188` 原子写已核实健康）→ **采纳报告二**，debounce 移除；规模化对策改为「迁 SQLite/JSONL」（触发式观察项）。
3. **状态码分类 vs 权威标记**：非冲突，合并为一项的两层——**分类先行**（TRANSIENT 不切号）+ **终局判定需 body 确认**（401 无权威标记不进风控冷却、不换 device_id）。
4. **账号调度升级**（least-inflight / 健康度打分 / inflight 可配）：报告一判观察（池小），报告二 P2-1/P2-2 提出带约束方案 → 合并为单个观察项「账号池调度升级包」，注明**D3 拍板取舍、实施需重新拍板**。
